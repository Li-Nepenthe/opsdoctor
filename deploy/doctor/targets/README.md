# 系统接入目录

医生不读取靶场代码。它先看这里的配置，知道去哪查指标、调用链和日志，再读对应的系统说明书，知道服务和表各自负责什么。

`shop.yaml` 是真实接入配置，密码位置只写环境变量名。`shop.profile.md` 只描述架构，不列故障清单或排查答案。新增系统时放另一份 YAML 和说明书，并使用以新系统名开头的独立账号变量。启动时会检查重名和共用凭据，失败时不会接收告警。

这个目录以只读方式挂到医生容器。不要把实验目录、恢复记录或 Docker socket 一起挂进去。配置格式见计划书第 5.5.2 节。

每个系统还必须填写 `alert_recovery_window`。它回答的是：所有告警刚刚恢复以后，再等多久才认定这场故障结束。shop 中最慢的告警要持续 2 分钟才发出，再加 10 秒规则评估和 5 秒通知等待，至少需要 135 秒，因此这里填 3 分钟。晚到的症状归入原诊断，页面单独展示，不再花钱重写报告。若这期间确实发生新的独立故障，可以手动发起诊断。新增或延长告警规则后，仓库测试会检查这个时间是否仍足够。

说明书还列出架构中的组件标识。服务、模块、表和调用链路采用固定写法，报告只能从这张表中选择；证据不足时用 unknown。组件表由架构推导，不能根据某次实验答案临时添加。表格放在 COMPONENTS_START/END 标记之间，每行第一列用反引号包住标识，启动时会校验重复和缺项。

阶段 7 的接入配置还可以指定 `mysql_ddl_dsn_env`、`write_timeout` 和 `ops_api`。前者绑定独立索引账号；运维服务清单固定地址、连接池范围和可以预热的服务。模型不能临时更改这些地址。写操作默认等两分钟，范围为三十秒到三分钟；准备审批只查元数据，仍用十秒上限。`mcp_token_env` 绑定外部只读客户端的独立令牌，连接方式见 [MCP 说明](../../../docs/mcp.md)。
