# deploy/mysql：MySQL 初始化

这里只负责“建库”和“建账号”，不负责建表。

- **建库、建账号**：由 [init](init/README.md) 里的脚本完成。MySQL 官方镜像第一次启动时（数据目录还是空的）会自动执行它们。
- **建表、改表**：由 Go 代码完成，见 `internal/shop/migrations`。这样表结构只有一个来源，不会出现两套脚本互相覆盖的情况。

## 要注意的一点

初始化脚本**只在数据目录为空时执行一次**。MySQL 的数据存在 Docker 数据卷里，删掉容器、重新启动，数据卷还在，脚本就不会再执行。

所以，后来新增的脚本（比如阶段 2 加的订单测试库）不会在已有的数据卷上自动生效，需要按根目录 README 的说明手动执行一次。不要为了让它重新执行就删掉数据卷，那会把造好的 200 多万条订单数据一起删掉。

## 内存设置

MySQL 容器的内存上限是 1.5 GiB。阶段 3 实测时，它已经用到原来 768 MiB 上限的 98.8%，所以调高了。InnoDB 缓冲池（MySQL 缓存数据页的内存）仍然是 256 MiB，最大连接数仍然是 100。调整理由和实测数据见阶段 3 汇报书。
