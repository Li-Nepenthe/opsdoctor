# doctor：从告警到有证据的诊断

系统变慢时，我们需要先把证据找齐。医生接收 Alertmanager 的通知，为同一次故障保存一个诊断。调度器让模型选择查看工具，工具结果再交回模型，直到提交一份通过校验的报告。页面实时显示保存下来的每一步，人也可以用 doctorctl 手动取证。

新环境默认使用 Mock：它按固定脚本走流程，不访问模型服务商，也不会给出真实根因判断。只有明确选择真实 provider，并配置费用上限后，才会发起付费请求。

先从 [app](app/doc.go) 看程序怎样启动，再按下面的顺序往里读：

| 包 | 要解决的问题 |
|---|---|
| [auth](auth/doc.go) | 怎样验证登录密码，以及签发、检查登录令牌 |
| [httpapi](httpapi/doc.go) | 怎样让登录用户调用工具，让每个系统用自己的令牌推告警 |
| [target](target/doc.go) | 怎样读取多份接入配置，并为每个系统单独建立连接和菜单 |
| [tools](tools/doc.go) | 哪些问题允许问，参数怎样校验，等待多久，结果太长怎么办 |
| [source](source/README.md) | 怎样向不同产品提问，再把不同格式整理成医生能处理的数据 |
| [alerts](alerts/doc.go) | 收到的通知是否完整，保存动作需要什么接口 |
| [store](store/doc.go) | 怎样保存任务、步骤和费用，同一场故障怎样只建一个诊断 |
| [llm](llm/doc.go) | 怎样与模型交换工具请求，发送前怎样脱敏、预留费用 |
| [agent](agent/doc.go) | 怎样控制每轮查证、并行工具、报告校验和预算 |
| [run](run/doc.go) | 谁先执行、最多执行几个、怎样取消和清理旧任务 |
| [events](events/doc.go) | 怎样通知页面，同时不让慢浏览器拖住诊断 |
| [web](web/doc.go) | 怎样在不引入前端构建工具的情况下展示实时过程 |

医生不导入 shop 或 chaos，也不读取实验场景和恢复记录。它认识 shop 的途径只有接入配置、架构说明和真实观测数据。archcheck 检查源码依赖和 Compose 挂载；运行时的只读账号限制实际能执行的命令。两层检查分别解决不同的问题。

新增接入系统时，先读 [targets 的说明](../../deploy/doctor/targets/README.md)。工具参数里不能临时填写地址或系统名。系统在创建工具菜单时就绑定好了。

阶段 7 增加 [approval](approval/doc.go)：把写操作变成一张人能核对的审批单，执行后保存结果。恢复时先确认目标系统的真实状态。

[mcpserver](mcpserver/doc.go) 把同一套只读工具开放给外部客户端，使用每个系统自己的令牌，并保存每次调用的审计。连接方法见 [MCP 文档](../../docs/mcp.md)。
