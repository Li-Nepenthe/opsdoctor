# chaos：把真实问题放进实验环境

如果只是让服务返回一条“出错了”的消息，就学不到索引、连接池和网络究竟怎样影响业务。这个目录里的程序会改动真实原因，再观察业务是否出现了预期症状。

程序在宿主机运行，能够改结构、重建容器，因此和业务服务分开。这里不放医生代码，也不替医生生成诊断结论。场景答案在 [eval/scenarios](../../eval/scenarios/README.md)，只供实验和以后的评测使用。

| 子目录 | 负责什么 |
|---|---|
| [scenario](scenario/doc.go) | 读取场景文件，先检查动作和参数是否合法 |
| [action](action/doc.go) | 真正修改索引、网络、配置、流量和消费者状态 |
| [verify](verify/doc.go) | 查询真实指标和告警，判断症状与恢复 |
| [app](app/doc.go) | 组织完整过程，保存恢复记录，处理失败与中断 |

先读一个场景 YAML，再沿着 app → action → verify 看它怎样执行。实验前需要有真实流量和足够库存。命令入口是 [cmd/chaos](../../cmd/chaos/main.go)。
