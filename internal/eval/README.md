# eval：安排实验、保存结果和比较报告

医生不能知道哪个场景正在注入，也不能读取标准答案。评测器在宿主机运行，负责安排实验，再从医生那里取回报告。答案只用于事后的比较，不会装进诊断提示或系统说明书。

| 目录 | 负责什么 |
|---|---|
| [runner](runner/doc.go) | 保存运行配置，暂停自动告警诊断，用同一个输入建立实验任务 |
| [scoring](scoring/doc.go) | 对组件作精确比较，从真实工具表格核对规则型证据 |
| [judge](judge/doc.go) | 让另一家模型按固定标准评价机制与其余证据，检查引用是否真实 |
| [report](report/doc.go) | 从已保存的报告提取真实用量，导出可阅读表格 |

用户审过手册和试跑后，`freeze` 固定五配置的随机顺序与版本，`run` 执行同一故障上的 Terra 四组和 DeepSeek E1。两种币种各走自己的预算账户。命令中断后沿用批次编号，读取已经保存的轮次、诊断与评分；原失败不会被补跑覆盖。

`export` 只读数据库，导出明细和分层的均值、范围、样本数。`calibrate` 只在批次完成后抽二十份，保存编号并输出空白盲评表。程序不会替用户打分。生成表后必须停下来等用户。

正式开始前还要完整跑一次五配置和评分检查。代码已接线不等于正式实验已经完成；真实结果以数据台账为准。
