# scenarios：一份文件描述一次实验

每个 YAML 文件包含六部分：编号与标题、注入动作、恢复动作、症状查询、原因解释、调查时应收集的证据。`inject` 和 `restore` 是按顺序执行的列表，因为有些场景要同时改配置和网络。

`symptom.promql` 是交给 Prometheus 的比较表达式。请使用普通的 `>`、`<` 等过滤比较，不加 `bool`：条件成立时留下样本，不成立时返回空列表。`alerts` 列出允许计入验收的相关告警。症状与至少一条相关告警都出现，verify 才通过。

| 文件 | 改动的真实原因 |
|---|---|
| [S01](S01.yaml) | 删除库存商品索引 |
| [S02](S02.yaml) | 删除订单列表联合索引 |
| [S03](S03.yaml) | 将库存连接池设为两条 |
| [S04](S04.yaml) | 关闭合并回源，删除热点缓存，逐批发送有上限的商品查询 |
| [S05](S05.yaml) | 关闭过期抖动，让一批商品缓存共同到期 |
| [S06](S06.yaml) | 停止消费者 |
| [S07](S07.yaml) | 增加订单至库存的响应延迟 |
| [S08](S08.yaml) | 让订单集中更新同一库存行 |
| [S09](S09.yaml) | 发布另一个响应收尾实现 |
| [S10](S10.yaml) | 增加库存至 MySQL 的响应延迟 |
| [S13](S13.yaml) | 缩短单次查询等待，并关闭退避和熔断、提高重试上限 |

恢复发布与流量时，工具使用注入前保存的实际配置。YAML 中的恢复列表决定顺序，不会强行把用户原有配置覆盖成示例默认值。缓存删除无法还原原字节，但正常请求会重新填充；工具绝不清空 Redis 或修改订单幂等记录。

标准答案只存在于宿主机。这些标题和解释不会写进业务日志、指标、版本号或调用链。S11、S12 属于阶段 8，本目录暂不提供。
