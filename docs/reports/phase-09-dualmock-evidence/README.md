# 双 Mock 入口检查原件

这个目录保存 `phase09-dualmock-20261103T171411Z` 完整流程结束后，入口检查实际读取的证据副本。医生使用 Mock，评委使用 Mock；其中的诊断与占位评分用于核验注入、查询、审计、评分保存、恢复和导出流程，不能当作泛化成绩，也没有重新评分已有的真实诊断。

[原 Gate JSON](../phase-09-dualmock-entry-gate.json) 保留原始内容和 TEMP 路径。[manifest.json](manifest.json) 将每个证据原路径及采集来源映射到仓库路径，并记录逐字节 SHA-256 和大小。所有源文件先通过大小与摘要校验，再以独占新建方式复制；目的文件随后再次核对。文件名沿用 Gate 的编号，`.log` 文件也可能保存 JSON，不做格式化或换行转换。

[gate-helper.py](gate-helper.py) 是这次实际执行的入口检查脚本快照，摘要必须与原 Gate 的 `helper_sha256` 一致。它不是需要在归档目录运行的程序；此处只供审查。脚本的登录响应与访问 token 只留在运行内存中，从未写入证据文件；本目录不保存登录 token、私有环境文件或请求认证头。

`pilot2-cost-attempts-only` 文件只保留原试跑的费用尝试记录，供分币种估算预算。它不把旧试跑的诊断或失败评分加入双 Mock 成绩，也没有修改或补评旧评分。DeepSeek 余额文件来自免费余额查询；归档动作本身仅复制本地文件，没有访问服务、Docker 或模型。

归档保留 Collector 原日志、起点锚点、窗口审计与摘要，以及 baseline、症状、恢复和原开关恢复证据。有关数据是否正常的判断仍以原 Gate 及各原件为准；Mock 流程通过不能替代正式诊断结果。
