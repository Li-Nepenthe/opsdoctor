## 网络实测

探测程序用 Go 1.27.1 编译为 Linux 纯 Go 二进制，在正在运行的 doctor 容器内执行。和生产客户端一样，使用默认 HTTP Transport、容器证书、连接复用和环境代理规则，禁止重定向。Key 只从容器环境变量读取。只访问 [OpenAI 模型列表接口](https://developers.openai.com/api/reference/resources/models/methods/list)，没有生成请求或付费调用。

串行请求最多每五秒一次，单次上限六十秒，不重试。总时长由单调时钟控制，为 **600.003 秒**。实际 **109 次，107 次成功，2 次失败，失败率 1.83%**。成功请求耗时 348–1689 毫秒，中位数 853 毫秒。

| 请求序号 | 结果 | 实测耗时 | 收到第一个响应字节 |
|---:|---|---:|---|
| 99 | network_error，无 HTTP 状态 | 60002 毫秒 | 否 |
| 100 | network_error，无 HTTP 状态 | 小于 1 毫秒，原记 0 | 否 |

第 100 次的 0 是整数毫秒显示值，不代表请求成功或没有发送。此次只分类网络结果，没有保存底层异常原文，尚不能判断是 DNS、代理还是上游连接问题。显式代理判定为 false，也不能排除 Docker 或宿主机透明代理。

完整记录：[109 次网络请求](phase-08-network-preflight.jsonl)。探测二进制临时放在已有只读 targets 挂载中，执行结束后已移除；没有改容器网络、代理、证书或系统时钟。

## 时钟实测

最初五次 SQL 采样中，数据库比宿主机请求前后时间的中点快约 554–630 毫秒。此轮容器 date 只有一秒显示精度，随后改用 Go 的纳秒日期格式补测。

在宿主机 UTC 09:47:14–09:47:15 的五轮补测中，doctor 容器比宿主机中点慢 **10.010–10.080 秒**，doctor-mysql 慢 **10.005–10.073 秒**。一次往返约 107–125 毫秒，中点估计有约半个往返的误差，不能宣称精确同步。请求前后时间和分辨率见[时钟采样](phase-08-clock-preflight.json)。

网络记录中，相邻请求的墙钟开始时间出现 **19 次倒序**。墙钟起止仅相差约 589.978 秒，而单调时钟测得 600.003 秒。这里只记录回拨，没有证据把它归因于某个校时软件。统一时区之后，仍不能拿日期相减当耗时。
