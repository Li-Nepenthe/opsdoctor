## 三、代码明细

新包 `internal/eval/runner` 负责实验流程；`judge` 负责模型评分协议；`scoring` 负责可由程序判定的证据；`report` 负责统计、导出与盲评表。`internal/platform/clockcheck` 比较日期与单调时间，阻止时钟跳变污染实验。

医生的 agent、run、store、tools、httpapi 与页面增加实验上下文、执行配置、查询窗口和结果读取。chaos 增加 S11、S12 的真实动作。医生仍不能导入 eval 或 chaos，也不能读取场景答案和恢复文件。

核心调用顺序如下：

1. `cmd/eval → runner.RunCLI → freezePaired` 保存版本、随机顺序和预算。
2. `automatic → advanceTrial` 依次执行注入、verify、matrix、restore、冷却。
3. `matrix → executeSlot → Store.Evaluation` 创建或取回同一诊断；调度器按已绑定配置执行 Agent。
4. `gradeSlot → gradeInput → judge.Evaluate → Check` 保存评分。规则结果不能被评委覆盖。
5. `export → report.Markdown` 分模型、场景与组统计；`calibrate → SelectCalibration → Blind` 生成空白人工表。

逐文件行数、338 项类型与函数导航、89 个顶层测试见[代码清单](phase-08-code-inventory.md)。这份草稿暂以 `main...bc0bcc8` 的 188 个文件为准，最终收尾会更新差异。

迁移为 `0026` 至 `0039`，逐个文件的作用见 [迁移清单](../../internal/doctor/store/migrations/README.md)。新增 eval_runs、eval_attempts、eval_results、eval_trials、eval_interruptions、eval_calibration 等表，并保存执行身份、评委审计、单调时长和一次补跑的关联。失败不删除，续跑不重置 token。

新增登录后只读接口 `GET /api/v1/eval/runs`、`GET /api/v1/eval/runs/:id`；评测状态与配置沿用医生接口。没有新增对外端口。新增配置的名称、含义、默认值以[计划书第 5.8.4 节](../../项目计划书.md)为完整清单；包括 EVAL_TOKEN_BUDGET、EVAL_COMPARISON_* 和 EVAL_DEEPSEEK_HOLIDAYS。Key 只读环境变量。

Compose 沿用十九个项目容器，只扩展 doctor 的实验配置与通用手册只读挂载；没有向医生开放 Docker socket。

## 六、偏离计划之处

用户批准无响应网络错误最多两次额外重试，且未知预留不退回；批准将整数秒检查改为日期与单调增量差超过 100ms 才暂停。DeepSeek E1 从试跑时考虑的独立批次改为同次故障的第五组，减少注入次数，也让跨模型比较更公平。详情见[决定记录](../decisions.md)。

评分协议在正式冻结之前从 v1.0 升到 v1.1，原因是待评项目边界不清；旧失败和费用不改写。手册已按 Claude 意见升到 v1.1。

## 七、已知问题与遗留事项

正式评测和人工一致率尚未完成，不能宣称总体准确率。正式每个场景也只有三次，必须同时展示平均、范围与样本数。环境是自建靶场，跨供应商评委仍是模型，人工校准才能揭示其偏差。

部分 MySQL 指标与 SQL 摘要是进程累计值，无法全部按故障时间裁剪；报告仍可能看到以前执行过的 DDL。未知网络请求保留最大预留，账本可能高于实际费用。OpenAI 项目 Key 无权读取实际账单，最后需用户到平台核对；DeepSeek 余额遇到充值时，不能用净差直接计算花费。

CacheLoadsHigh 在五十万商品工作集下的误报仍按用户要求另做。本阶段使用一万商品基线，不通过改默认值或告警规则掩盖这个问题。
