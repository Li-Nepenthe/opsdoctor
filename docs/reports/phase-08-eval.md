## 三、代码明细

`internal/eval/runner`安排实验，`judge`校验模型评分，`scoring`判断规则证据，`report`负责汇总和盲评。`internal/platform/clockcheck`比较日期增量与单调时间增量。新增包的doc.go和分组README说明了阅读顺序。

医生的agent、run、store、tools、httpapi和页面增加了实验上下文、按诊断绑定模型、查询窗口与结果读取。chaos增加S11、S12动作。医生仍不能导入eval或chaos，也读不到场景答案和恢复文件。

主要调用顺序：

1. `RunCLI → freezePaired`保存版本、随机顺序和预算。
2. `automatic → advanceTrial`推进注入、验证、诊断、恢复与冷却。
3. `matrix → executeSlot → Store.Evaluation`创建或取回同一槽位的诊断。
4. `gradeSlot → judge.Evaluate → Check`保存评分，不能覆盖规则判定。
5. `export → report.Markdown`分层统计；`calibrate → SelectCalibration → Blind`固定抽样并导出空表。

252个自有文件改动、367项类型与函数、103个顶层测试见[代码清单](phase-08-code-inventory.md)。文件地图已重新生成，共425个非生成Go文件。

医生库迁移0026–0042的作用见[迁移清单](../../internal/doctor/store/migrations/README.md)。结果、轮次、原中断、补跑关联、预算和执行版本分别留档，续跑不重置费用或token。新增登录后只读接口`GET /api/v1/eval/runs`和`GET /api/v1/eval/runs/:id`；没有新增公开端口。

配置以[计划书第5.8.4节](../../项目计划书.md)为准，包括EVAL_TOKEN_BUDGET、EVAL_COMPARISON_*与闲时价格配置。Compose仍为十九个项目容器，只扩展doctor实验配置和手册只读挂载，未开放Docker socket。

## 七、已知问题与遗留事项

每场景只有三次，环境是自建靶场。配对仍是依次执行，后跑组看到不同的故障时刻；随机排序只能减少固定偏向。S02补跑间隔超过一小时，是额外比较限制。

S12的15份报告全未读到攻击文字，不能用零写执行证明抵抗提示注入。评委却对若干未观察的项目给分，原评分不改写。还发现复合里程碑只满足一半就给分、误把告警速率当放大倍数、引用错误类型的步骤等问题。二十份人工抽样只覆盖有效评分，无法用它掩盖14份格式或协议失败。

部分里程碑要求修复后症状消失，但本次评测禁止批准写操作，且评分在restore之前，因此医生不能获得那部分观察。正式冻结后没有删分母；覆盖率必须带着这个限制阅读。

默认前五分钟窗口仍可能带入历史抖动，模型主动扩大窗口更容易混入旧故障。故障开始时间也可能早于部署动作全部完成；S13第三轮的DeepSeek拿到新版启动前的Redis慢链，不能据此证明新配置下的重试。MySQL累计摘要也不能完全按时间裁剪。

DeepSeek对比与评委同一家，跨供应商评委的好处只适用于Terra一侧，不能宣称消除了偏差。账本与实际扣费差额仍需核对。CacheLoadsHigh在五十万工作集下的规则问题继续留作另项，不在本阶段修改。
