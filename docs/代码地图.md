# OpsDoctor 代码地图

读代码时迷路了，就回到这里。它回答两个问题：每个目录是干什么的，每个文件是干什么的。

**怎么用：** 先在“目录结构”里找到要去的目录，再到最后的“Go 文件清单”里查这个目录下每个文件的一句话说明。想了解得更详细：

- 每个分组目录（比如 `internal/platform`）有一份 `README.md`，介绍里面的子目录；
- 每个 Go 包有一个 `doc.go`，介绍这个包做什么、每个文件负责什么、从哪里开始读；
- 每个 `.go` 文件开头有“本文件：”说明，介绍这个文件的作用和主要函数。

## 目录结构

```text
opsdoctor/
├── cmd/                         每个可运行程序的入口，一个子目录一个程序
├── internal/                    全部实现代码
│   ├── platform/                通用基础设施：配置、日志、数据库、迁移、停机、HTTP/gRPC 公共处理、服务治理、可观测性
│   ├── shop/                    靶场（电商业务）
│   │   ├── app/                 各程序的组装代码：读配置、连依赖、启动服务
│   │   ├── inventory/           库存：扣减、归还、查询
│   │   ├── inventoryclient/     订单服务调用库存服务的客户端：超时、重试、熔断
│   │   ├── product/             商品查询和缓存
│   │   ├── order/               下单、查订单、接口幂等
│   │   ├── events/              Kafka 消息的格式、发送和消费
│   │   ├── sales/               销量统计：消费消息，并防止重复计数
│   │   ├── ops/                 内部运维：有限调池与缓存预热
│   │   ├── migrations/          靶场的建表 SQL
│   │   └── seed/                造测试数据
│   ├── doctor/                  医生：登录、工具、Agent、审批、租约恢复、MCP 与实时页面
│   ├── chaos/                   宿主机故障实验：场景、动作、验收和恢复
│   ├── loadgen/                 压测工具：生成流量、统计结果
│   └── eval/                    宿主机评测：冻结输入、试跑、保存结果
├── api/                         gRPC 接口定义（.proto 文件）
├── gen/                         由 .proto 自动生成的 Go 代码，不要手改
├── eval/scenarios/              实验定义与参考答案，不进入医生容器
├── deploy/                      Docker Compose 和各组件的配置
├── tools/                       代码规范检查与 Mock 进程恢复验收
└── docs/                        学习材料、汇报书、决定记录、实测数据
```
