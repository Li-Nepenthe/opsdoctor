# OpsDoctor 代码地图

这里是当前代码的总入口。先看目录分工，再进入包的 doc.go，最后打开文件顶部的“本文件”说明。生成文件是唯一不要求手写讲解的 Go 代码；业务入口在 main.go 用包说明代替文件说明。

## 当前结构

```text
opsdoctor/
├── api/proto/inventory/v1/       库存契约
├── gen/inventory/v1/             已提交的生成物
├── cmd/                         三个服务、loadgen、shopctl 与 alertsink 薄入口
├── internal/
│   ├── platform/                配置、日志、连接、迁移、协议保护、退出、resilience、telemetry 与 alertsink
│   ├── shop/
│   │   ├── app/                 公用配置；三个服务和 shopctl 的组装
│   │   ├── inventory/           模型 → 业务 → 仓储；gRPC 适配
│   │   ├── inventoryclient/     超时、重试和熔断
│   │   ├── product/             商品缓存、查询与库存降级
│   │   ├── order/               下单、查询、补偿与幂等状态
│   │   ├── events/              Kafka 契约、发送与手动提交
│   │   ├── sales/               去重事务与销量核对
│   │   ├── migrations/          五张 shop 表
│   │   └── seed/                批量种子基线
│   ├── doctor/auth/             未接线的认证包
│   └── loadgen/                 真实流量、控制与统计
├── deploy/                      Compose、Dockerfile、MySQL 初始化与监控配置
├── tools/                       commentcheck 与 archcheck
└── docs/                        设计、实测、汇报和学习材料
```
