# 进程和并发排查：增长不一定是泄漏

先确认进程运行多久、当前流量多少，再看 CPU、内存、goroutine 数和响应时间的走势。goroutine 是 Go 里执行并发工作的轻量任务。启动、连接建立和流量爬升都会增加它的数量。单个高值不能证明泄漏，需要看任务完成后能否回落。

比较几个时刻的堆栈摘要。堆栈显示任务目前停在哪个函数。大量任务停在同一个位置，是缩小范围的线索，但不直接说明那个函数有错：它可能在正常等待，也可能被下游拖住。结合等待持续时间、请求数和取消信号继续查证。

看上游请求数与下游尝试次数是否同步变化。一个请求可能合法地访问多个下游，也可能重试同一次调用。先核对正常比例，再看异常期间的增量。重试次数、每次尝试的时间预算、总预算和退避时间要一起看；只加重试次数可能放大负担。

限流是在入口拒绝过多请求，熔断是在下游持续失败时暂缓调用。它们触发后错误数可能上升，同时下游请求反而下降。需要区分保护措施的表现和最早导致保护生效的异常，不能把保护开启本身当作完整解释。

修复后在相同负载下继续观察。任务数回落、等待解除和错误减少应当相互支持。涉及扩大并发、连接或内存的建议，要写清是否只是缓解，以及新的资源压力会落到哪里。
