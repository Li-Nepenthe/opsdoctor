# 先把时间和证据对齐

旧故障留下的日志可能还在，新故障的调用链却还没采到。先写下本次症状的开始时间、查询的结束时间，以及它们使用的时区。比较故障前的一段健康数据，再看故障后的变化。不要拿不同时间的几个极值拼成一条因果链。

指标是持续采样的数字，适合回答“从什么时候开始、影响多大”。调用链记录一次请求走过哪些步骤，适合回答“这次请求在哪儿等”。日志记录某件事发生时的文字，适合解释错误和配置。三者的时间能对上，结论才更可靠。

计数器的总值会随着程序运行增长。比较当前变化速度，而不是直接比较累计总量。进程重启会让计数器归零；计算时要考虑这次重置。百分位数描述一批请求的分布，例如 P99 表示约百分之一的请求比它更慢，不是一条固定请求的耗时。

没找到调用链可能是没有采样、超过保留时间、筛选条件太窄，也可能是调用根本没发出去。先检查采集是否可用，再把“没看到”和“没有发生”分开写。结果被截断时，也不能把省略的部分当作不存在。

最后分三栏记录：直接看到的事实、由事实推出来的解释、还缺什么证据。没有异常的结论也需要覆盖主要链路和足够的时间范围，不能只凭一条健康检查。
